# M1 — Trace dissection: where do the tokens go?

Course base: W1 (trace dissection). Capture Claude Code and pi through mitmproxy, then account for every token:
system prompt, tool schemas, tool results, cache reads/writes.

## Setup (2026-11-09)
- mitmproxy 11.0.2 via `uv tool install mitmproxy` (isolated venv).
- `tracer/run.sh <label> <cmd...>`: starts `mitmdump` on 127.0.0.1:18080 with `tracer/capture.py`, runs the command with
  `HTTPS_PROXY` + `NODE_EXTRA_CA_CERTS`. **CA trusted only by that child process**, never by the system keychain.
- `tracer/capture.py` writes redacted JSONL (auth headers, cookies, token/secret JSON keys) to `traces/DATE/label.jsonl`.
  No `-w` flows file: raw flows would contain credentials. SSE is streamed through live and teed, then reassembled into
  the final message.
- `tracer/report.py summary|dump`: per-request breakdown (chars/4 estimates per component; exact totals from `usage`),
  and a markdown dump of one request (system blocks, tools, messages, response).
- Verified: no `sk-ant-`, `Bearer`, or token values in the trace or mitm log.

## First capture: `claude -p "Reply with just: hi"` (Claude Code 2.1.285, Opus 5.5)
- **21 HTTP flows for a one-word answer**, only 1 is `/v1/messages`. The rest: MCP registry (4×, ~220KB each),
  OAuth org/account lookups, feature flags (`grove`, `penguin_mode`, `bootstrap`), connected MCP servers via
  `mcp-proxy.anthropic.com`, event logging (one batch ~400KB), Datadog logs.
- The one model call: **~17k input tokens to say "hi"**: `cache_read=8368`, `cache_write=8666` (all 1h TTL), `input=2`, `output=4`.
- Request layout:
  - `system[0]`: billing header as text (`cc_version`, entrypoint, prompt id); `system[1]`: "You are a Claude agent, built on the Agent SDK" (because `-p`)
  - `system[2]`: core prompt, `cache_control {ttl: 1h, scope: global}`. **Global scope** = shared across users,
    which is likely why even the first call reads ~8.4k from cache.
  - `system[3]`: session-specific part (1h TTL).
  - 12 tools ≈ 5.5k est. tokens; the rest are **deferred** behind `ToolSearch` (names only, schemas on demand).
  - A mid-conversation `system`-role message (~4.3k est.) carrying environment/skills/agents context, cached.
- Other fields: `thinking: adaptive` (display omitted), `context_management: clear_thinking`, `output_config.effort: medium`,
  `thread`, `diagnostics.previous_message_id`, `max_tokens: 128000`; 18 `anthropic-beta` flags.
- chars/4 undercounts (≈12k est. vs 17k real); JSON tool schemas tokenize denser than prose. Use `count_tokens` for exact per-component numbers.

## Version diff: Claude Code 2.1.285 → 2.1.311 (same `-p` prompt, `tracer/report.py diff`)
- Input **17.0k → 18.0k tokens** (cache_read 8368→9013, cache_write 8666→8948): ~+5% context for a no-op prompt in 26 releases.
- Same 12 tools, same request fields. Tool descriptions grew: Agent 829→1027 est. (fork subagents, background-by-default text),
  Bash 844→955, Read 417→501.
- Beta flag `mid-conversation-system-2026-04-07` dropped (the system-role message is still sent; presumably folded into GA).
- Prompt changes are mostly safety/behavior text: a longer `<pasted_content>` rule (act on a pure paste; embedded instructions in
  docs/logs aren't requests), a new rule that downloaded files are untrusted (separate dirs, `python -I`, planted `json.py`),
  `/code-review` gained `--max-findings` and "never use max/ultra on your own judgment".
- Model list in the environment block: Haiku 4.5 → **Haiku 5.5** (`claude-haiku-5-5`). The prompt is also a release-notes channel.
- Takeaway for the harness: a frontier client's fixed prefix drifts upward release over release; it is all cached, so the
  cost is mostly cache writes (1h TTL: 2× base input price) on each new session or version.

## pi 1.5.1 vs Claude Code 2.1.311 (same prompt, same model `claude-opus-5-5`)
Setup: `npm i -g --ignore-scripts @earendil-works/pi-coding-agent@1.5.1` (renamed from `@mariozechner/...`, which stopped
updating in May). Needed Node ≥23.8 (bundled undici uses zlib zstd): `brew upgrade node` 23.7 → 26.13.
Auth: separate Console workspace `frugal-harness` with a spend limit; key in macOS Keychain, `~/.pi/agent/auth.json`
holds only `"key": "!security find-generic-password -ws anthropic-frugal"`. pi honors `HTTPS_PROXY` natively.

| | Claude Code 2.1.311 (`-p`) | pi 1.5.1 (`-p`) |
|---|---|---|
| HTTP flows | 20 (1 model call) | **1** |
| input tokens to say "hi" | ~18.0k (9.0k read + 8.9k write) | **~2.3k** (all cache write) |
| cache TTL | 1h (writes cost 2× input) | 5m (writes cost 1.25× input) |
| cache scope | `global` on core prompt (cross-user hit) | none (default) |
| system prompt | 4 blocks + system-role message ≈ 6.5k est. | 1 block ≈ 570 est. |
| tools | 12 full + deferred via ToolSearch ≈ 5.9k | 4 (read/bash/edit/write) + deferred placeholder ≈ 885 |
| beta flags | 17 | 4 |
| thinking / effort | adaptive, display omitted / medium | adaptive, display summarized / low |
| telemetry | event logging, Datadog, feature flags, MCP registry | none observed |

- pi's system prompt is ~25 lines: tool list, rules, pointers to its own docs (read on demand), cwd. Everything else
  is pulled in by the model when needed. That's the minimal-context design to beat (or match) in M2.
- 18k vs 2.3k is not a fair "efficiency" comparison: Claude Code ships agents, skills, MCP, scheduling, review. The
  question for M2/M3 is which of those tokens buy task success.

Scratch repo [m1-tokenledger](https://github.com/arosenfeld2003/m1-tokenledger), a submodule at
`experiments/m1-tokenledger` pinned to tag `start` (its own repo, per the assignment): a usage-block → dollars ledger, 3 modules

Same prompt for both agents, run from `experiments/m1-tokenledger`. After each run, save the result on a branch
(`git switch -c cc-result && git commit -am ...`), then `git checkout start && git clean -fdx`:
> `pricing.cost_usd` was deleted during a refactor and other modules still import it. Make a short plan first,
> then restore it so the full test suite passes. Run the tests to confirm.

### Run 1: Claude Code 2.1.311 interactive (2026-11-21), result on `cc-result`
- 5 main `claude-opus-5-5` calls + 2 Haiku helpers (quota probe, session title), 42 flows total. All 11 tests passed on the
  first test run; only `pricing.py` edited. Tools used: Bash only (ls/grep, heredoc append, pytest), no Read/Edit and no
  todo list. One failure: zsh rejected the glob in `grep --include=*.py` (`is_error: true`), and the next call
  dropped the flag. So the task did not meet the assignment's "plan" or "fails at least once" requirements → needs a harder v2.
- **Server-side threads** (`message-threads-2026-08-12` beta): call 1 sends the full request with `thread: {type: create}`.
  Calls 2–5 send `thread: {type: continue, previous_message_id}`, **one message (the new tool_result), no tools, and only
  the billing-header system block**. `cache_read` still grows 25k → 43k, so the server rebuilds the prefix. The upload
  is the delta, the billing is not: every turn still pays cache reads on the whole context.
- Call 1 prefix ≈ 38k tokens (tools ≈ 18k, of which Artifact ≈ 9.6k). 1h-TTL cache writes: 13.2k on call 1, then 0.2–3.5k per turn.

### Run 2: pi 1.5.1 interactive (2026-11-21), result on `pi-result`
- 5 main calls, 14 flows. Also passed all 11 tests on its first test run, editing only `pricing.py` (bash heredoc append, like
  Claude Code). Tried `uv run pytest` first, which left an untracked `uv.lock` (not committed).
- **Did make the plan the prompt asked for**, as visible text in call 1 ("Plan: 1) inspect … 2) restore … 3) run tests").
  Claude Code ignored "make a short plan first" with the same prompt. Its auto-mode prompt says "When you have enough
  information to act, act", which may explain it [INFERRED].
- **Also uses server-side threads** (`message-threads-2026-08-12`, plus `inline-tools`, `thinking-binding-controls`,
  `mid-conversation-output-config`; 4 betas vs Claude Code's 20), so threads work with a plain API key.
- Correction to Part 1: pi does phone home. On first launch it downloaded `fd` + `ripgrep` from GitHub, sent
  `pi.dev/api/report-install`, checked the latest version, and fetched its model/price table from `pi.dev`.
  Claude Code: Datadog logs, event logging, MCP registry, OAuth, GitHub API (repo + PR lookup), brew/release checks.

### Same task, same model: Claude Code vs pi
Real first-party prices: Opus 5.5 $4/$20 per M tokens, cache read $0.20, cache write 1.25× (5m) / 2× (1h). pi's footer
agreed to the cent. (The tokenledger test fixture still uses older $5/$25 prices; it's a toy.)

| | Claude Code 2.1.311 | pi 1.5.1 |
|---|---|---|
| main calls / tool calls | 5 / 4 (Bash) | 5 / 4 (bash) |
| tests passed on first run | yes | yes |
| wrote the requested plan | no | yes |
| first-call prefix | ~38k tokens (tools ~18k) | ~2.4k tokens |
| cache TTL | 1h (writes 2×) | 5m (writes 1.25×) |
| cost (API-equivalent) | **$0.234** (writes $0.148, reads $0.038, output $0.048) | **$0.073** (writes $0.034, reads $0.004, output $0.036) |
| model time | 30.8s | 24.3s |

- Claude Code costs 3.2× more for the same outcome, and 63% of its bill is cache writes: a 38k prefix written at the
  1h rate. The 1h TTL only pays off if the session comes back within the hour; for a one-shot 5-call task it's pure overhead.
- Output tokens are close (2.4k vs 1.8k). The difference is almost all fixed prefix, which is what M2 controls.

### v2 task (graded capture for week1 Part I)
Run 1 was too easy: no plan, and the only failure was a shell glob. Branch/tag `v2-start` in the scratch repo
starts from a completed v1 and adds `ISSUE.md`, `PRICING.md` and `tests/test_issue.py` (9 failing acceptance tests).
The issue requires edits to `pricing.py`, `ledger.py`, `cli.py` and both old test files. Traps:
- the old `family()` lookup matches by substring, so `claude-opus-5` would get Opus 5.5 prices and `claude-opus-4-8` would

- the old tests hardcode the old prices, so the agent must recompute expected values by hand;
- `test_cache_read_is_tenth_of_input` passes at the start and **only fails once the new prices land**: the test, not the
  code, is wrong, and the issue forbids deleting tests.
The reference solution (20/20 passing) is at `~/.local/share/cs146s/m1-reference/v2/solution.diff`, outside both repos.

### Run 3: Claude Code v2 (2026-11-22), result on `cc-v2-result`
- 9 Opus calls + 2 Haiku helpers, 52 flows, **$0.415** at real prices. 21/21 tests pass, same count as at the start (no
  deletions). 5 files changed; its expected values match the reference exactly. It kept `family()` and `test_family`.
- **Avoided every trap with no failed test run.** Call 2 ran the baseline (9 failures), then it rewrote `pricing.py` with
  exact-ID lookup and pre-emptively renamed and fixed `test_cache_read_is_tenth_of_input` before running anything. The
  only red output in the session is the planted baseline.
- **Plan = text, not a tool.** The session's 15 tools have no TodoWrite/Task tool. The plan appears as a
  `display: "updates"` thinking block ("I'm working through a five-step plan: …"), then "Task 1 … Task 5" text headers.
- **Mid-conversation tool changes:** call 1 carries `role: "system"` messages of `type: "tool_addition"` (three Claude Docs
  MCP tools) instead of growing `tools[]`, so the cached tools prefix stays stable (`mid-conversation-tool-changes` beta).
- **Hidden post-turn call:** after the final answer, Claude Code sends one more Opus request **without a thread**,
  replaying the whole conversation plus `[SUGGESTION MODE: Suggest what the user might naturally type next…]`. It returned
  "commit this" (5 output tokens) and cost $0.018 (50k cache reads), about 4% of the session.

## Caveats
- `-p` runs as the SDK entrypoint (`sdk-cli`), so its prompt differs from the interactive CLI. Capture interactive sessions too.
- The proxy changes networking only; the client is the same binary with the same flags.
